# ITScan Telegram Bot

Telegram-бот с RAG (Retrieval-Augmented Generation), который отвечает на вопросы по IT, используя статьи, спарсенные из RSS-лент Хабра.

## 📋 Обзор

ITScan - учебный проект на **Java 21 + Spring Boot 4 + Spring AI**. Бот:

- парсит **RSS-ленты** Хабра (карьера, исследования, стартапы, статистика),
- разбивает статьи на **чанки** и сохраняет их в **pgvector**,
- отвечает на вопросы пользователей через **RAG** (`retrieval → prompt → LLM`),
- работает в **Telegram** через long polling,
- поддерживает оплату через **Telegram Stars**.

Проект создан для закрепления концепций **RAG** и практики **Spring AI**, **pgvector**, **Docker** и **Telegram Bot API**.

   ┌──────────┐   ┌──────────┐    ┌──────────────┐
   │ /start   │   │ /ask     │    │ /buy, /profile│

   └──────────┘   └────┬─────┘    └──────────────┘
                       │
                       ▼
              ┌──────────────────────┐
              │   RagService         │  ← ChatClient + Advisor
              │   (QuestionAnswer)   │
              └──────────┬───────────┘
                         │

              │   LM Studio (LLM)    │  ← OpenAI-совместимый API

**Два инстанса PostgreSQL:**

- `postgres-user` - пользователи, состояния, счётчики запросов (JPA).
- `pgvector-itscan` - векторное хранилище для RAG (Spring AI).

Оба живут в Docker-сети `dbnet`. Наружу проброшен только HTTP-порт бота локально.

## 🚀 Технологический стек

**Backend**

- Java 21 - основной язык
- Spring Boot 4 - фреймворк приложения
- Spring AI - ChatClient, VectorStore, TokenTextSplitter, QuestionAnswerAdvisor
- Spring Data JPA - хранение пользователей
- Spring Scheduling - парсинг RSS по расписанию
- Spring Async - неблокирующая обработка сообщений через кастомный пул потоков
- ROME - парсинг RSS/Atom
- Jsoup - очистка HTML

**AI**

- LM Studio - локальный LLM-сервер с OpenAI-совместимым REST API
- Чат-модель: `qwen/qwen3-8b`
- Embedding-модель: `text-embedding-nomic-embed-text-v1.5` (768 dims)
- pgvector - расширение Postgres для хранения векторов

**Telegram**

- `telegrambots` (long polling) - Bot API
- Telegram Stars (`XTR`) - оплата дополнительных запросов

**Базы данных**

- PostgreSQL - данные пользователей
- PostgreSQL + pgvector - векторное хранилище для RAG

**DevOps**

- Docker - контейнеризация
- Docker Compose - оркестрация двух БД + бота

**Тестирование**

- JUnit 5
- Mockito

## 🧩 Модули

| Модуль                | Назначение                                                    |
|-----------------------|---------------------------------------------------------------|
| **RssParserService**  | Парсит RSS в `Document` с метаданными `url`                   |
| **RssSchedule**       | Запускает парсинг каждые 12ч (настраивается)                  |
| **VectorService**     | Разбивает документы через `TokenTextSplitter` и сохраняет     |
| **RagService**        | Собирает промпт, вызывает LLM через `ChatClient` с advisor    |
| **UserService**       | Управляет пользователями, счётчиками запросов и состояниями   |
| **CommandHandler**    | Маршрутизирует Telegram-обновления в нужную `Command`         |
| **MainBot**           | Long-polling consumer, точка входа для всех обновлений        |

## 🛠️ Быстрый старт

### Требования

- Docker
- Docker Compose
- LM Studio (запущенный локально с загруженными chat + embedding моделями)

### Запуск

```bash
# 1. Запусти LM Studio, загрузи модели, стартуй сервер на http://localhost:1234/v1
# 2. Экспортируй секреты
export TOKEN_BOT=<токен-твоего-телеграм-бота>
export API_KEY_AI=<ключ-lm-studio-или-dummy>

# 3. Собери и запусти
docker compose up --build
```

При первом запуске:

- бот регистрируется в Telegram через long polling,
- планировщик парсит RSS-ленты через 25 секунд,
- векторы сохраняются в `pgvector-itscan`.

## 📚 Команды бота

| Команда    | Описание                                     | Доступ                 |
|------------|----------------------------------------------|------------------------|
| `/start`   | Приветствие и инструкции                     | Public                 |
| `/ask`     | Задать вопрос (нужен ≥1 запрос)              | Authenticated (auto)   |
| `/profile` | Показать баланс запросов и статус            | Authenticated (auto)   |
| `/buy`     | Купить +1 запрос через Telegram Stars        | Authenticated (auto)   |

Пользователи автоматически регистрируются при первом сообщении с базовым количеством запросов к AI (настраивается, по умолчанию 3).

## 🔄 RAG-пайплайн

```
RSS → Parser → Document(url) → TokenTextSplitter → chunks
     → EmbeddingModel → pgvector

Вопрос → EmbeddingModel → similaritySearch (top-K, threshold)
       → QuestionAnswerAdvisor → ChatClient → LLM → ответ
```

**Особенности реализации:**

- `TokenTextSplitter` настраивается через `RagProperties` (размер чанка, минимальный размер, keep separator).
- `PgVectorStore` использует **cosine distance** для быстрого приближённого поиска.
- `QuestionAnswerAdvisor` подставляет найденные чанки в промпт.
- Планировщик запускается каждые 12ч (настраивается через `parser.fixed-rate`).
- При успешном ответе счётчик запросов пользователя уменьшается.

## ✨ Возможности

- 💬 **Telegram-чат** - long polling, без вебхуков
- 🤖 **RAG по Хабру** - ответы на основе спарсенных статей
- 🧠 **Сохранение контекста** - найденные чанки добавляются в промпт
- 💳 **Оплата через Telegram Stars** - покупка дополнительных запросов за `XTR`
- 🔒 **Лимит запросов на пользователя** - счётчик в `User`
- ⚙️ **Настраиваемость** - размер чанка, top-K, threshold, расписание парсера
- 🐳 **Docker-first** - одна команда для запуска всего

## 🔒 Безопасность

- **Две изолированные БД** - пользовательские данные и векторы разделены.
- **Изоляция в Docker-сети** - наружу проброшен только HTTP-порт бота.
- **Секреты через env-переменные** - `TOKEN_BOT`, `API_KEY_AI`.
- **Нет паролей пользователей** - аутентификация делегирована Telegram.
- **Внутренние эндпоинты не публикуются** - бот общается с БД напрямую, публичного REST API для RAG нет.

## ⚙️ Конфигурация

Ключевые свойства в `application.yml`:

| Свойство                           | По умолчанию | Описание                              |
|------------------------------------|--------------|---------------------------------------|
| `telegram.bot.base-count-request`  | 3            | Бесплатных запросов на нового юзера   |
| `parser.init-delay`                | 25000        | Задержка до первого парсинга (мс)     |
| `parser.fixed-rate`                | 43200000     | Интервал парсинга (12ч)               |
| `rag.top-k`                        | 5            | Количество найденных чанков           |
| `rag.similarity-threshold`         | 0.7          | Минимальная cosine similarity         |
| `rag.chunk-size`                   | 500          | Токенов на чанк                       |
| `rag.embed-dimensions`             | 768          | Размерность эмбеддинга (должна совпадать с моделью) |

Секреты передаются через переменные окружения:

- `TOKEN_BOT` - токен Telegram-бота
- `API_KEY_AI` - ключ LM Studio (любое значение для локального)
- `POSTGRES_DB_*` - креды БД пользователей
- `PGVECTOR_DB_*` - креды векторной БД
